# Fantasy Naming Guide

## 目的

- Star Ring Codex の表示名を、`日本語 UI として読みやすい` ことを最優先にしたうえで、西洋ファンタジーの空気を持つ形へ寄せる。
- `英語の直置き`、`漢字と読みの乖離が大きい名前`、`意味が分からない雰囲気語` を避ける。
- backend の canonical id は維持し、表示レイヤーだけを設計する。

## 今回固定する結論

- 最優先は `常用で意味が通ること` である。
- プレイヤーが一瞬で意味を取れない名前は、それだけで体験を損なう。
- 主表示は、初見でも意味が取れる日本語を使う。
- 西洋ファンタジー感は、`固有音`、`異名`、`神話語` のどれか 1 つで足す。
- `主表示 + 補助表示` の 2 層に分ける。
- raw English は codex 内の別名や制作メモに留め、UI の主表示には使わない。
- 読み仮名は常設しない。必要なときだけ codex 詳細で補う。
- 外部辞典のカテゴリは、少なくとも `place / person / item / equipment` を受けられるようにする。

## 最優先基準

### 1. 常用であること

- 少なくとも、小説やゲームに慣れた読者が辞書なしで意味を取れる語を使う。
- 現代日本語として一般的でなくても、ファンタジー文脈で十分に流通している語なら採用してよい。
- 例:
  - `指輪` は可
  - `燐火` は可
  - `燐石` は可

### 2. 初見で意味が通ること

- 単語自体の意味が分かるか、文脈から用途や性質が推測できること。
- 名前を見た瞬間に「地名」「組織」「人物」「遺物」のどれかが見当つくこと。

### 3. プレイヤーを止めないこと

- `何これ` で止まる名前は不採用。
- 命名は世界観を足すためのものであって、理解を妨げるためのものではない。
- 困惑を生む名前、誤解を誘う名前、読みが分からない名前は、雰囲気が良くても落とす。

### 4. 造語や古語は必要最小限にする

- 造語、死語、古語、業界用語は、常用に近い裏付けがある場合だけ使う。
- 「辞書を引かないと意味が分からない語」は、原則として造語と同じ扱いにする。

## 判断ルール

候補名は次の順で判定する。

1. 初見で意味が通るか
2. 誤読しにくいか
3. 誤解しにくいか
4. 小説・ゲーム文脈で常用に近いか
5. そのうえで、西洋ファンタジーの空気を足せるか

この順番を崩さない。`雰囲気が出る` は最後に見る。

## 調査から見えたこと

### 読みづらさは「読めない」だけでなく「正解が分からない」でも起きる

- 表記と読みの距離が大きい名前は記憶と検索に弱い。
- 画面で一瞬見て理解する UI では、この弱点がさらに目立つ。
- そのため、`澱舟泊（テイシュウ）` のような「漢字から自然に読めない読み」を主表示に置くのは不利。

### 地名は「固有部分 + 地形や施設の普通名詞」が強い

- 地名研究では、土地名は地形や人間の利用形態と結びついた普通名詞を含むほど理解しやすい。
- このため、都市・港・砦・街道・修道院・谷・森のようなアンカー語を末尾に置くのが有効。

### その世界の内側から呼んでいる感じが重要

- 外からの翻訳名のように見える名前より、その土地の住人が普通に呼びそうな名前の方が自然に定着する。
- `White Oath Ring` のような直訳英語は、この点でかなり弱い。

## 命名方針

### 1. 主表示は必ず日本語として読める

- 良い:
  - `白誓の指輪`
  - `ベルファスト港`
  - `灰冠騎士団`
- 避ける:
  - `White Oath Ring`
  - `Belltide Wharf`
  - `澱舟泊（テイシュウ）`

### 2. 西洋感は「全部」に入れない

- 次のうち 1 つを選んで効かせる。
  - 固有音
  - 異名
  - 神話語
- 例:
  - `ベルファスト港`
  - `ベルファスト〈平和の壁の街〉`
  - `火蜥蜴（サラマンダー）`

### 3. 異名は補助表示に回す

- 主表示は短くする。
- 雰囲気や伝承感は 2 行目、tooltip、codex 詳細で補う。
- 人物の主表示に `セルカ〈トルース・ウォーデン〉` を入れるのではなく、
  - 主表示: `セルカ`
  - 補助表示: `停戦守`
  とする。

### 4. 意味が分かる語を最低 1 つ入れる

- 地名なら地形や施設名
- 組織なら社会的な母体
- 遺物なら物の種類
- 魔法なら作用や系統

### 5. スケールに合う語を使う

- 小拠点なのに `王都` や `世界門` のような大きすぎる語は使わない。
- 広域地方と一都市の名前づけを同じ重さで扱わない。

## 表示レイヤー

UI では、名前を次の 5 層で管理する。

### `ui_label`

- もっとも短い主表示
- 画面のカード見出し、ボタン、一覧で使う

### `ui_subtitle`

- 異名、役職、短い説明
- 2 行目や補助ラベルで使う

### `codex_label`

- 図鑑で使う正式表示
- 主表示より少し長くてよい

### `reading`

- 必要な場合のみ codex 詳細で見せる
- 主表示には常設しない

### `true_name`

- 真名、儀礼名、古名
- reveal 状態に応じて codex 内だけで解放する

## カテゴリ別の命名テンプレート

### 地名

形式:

- `固有名 + 港 / 街 / 砦 / 峡谷 / 森 / 修道院`
- `固有名〈短い異名〉`

例:

- `ベルファスト港`
- `アーデン街道`
- `グレイヴェイル修道院`
- `ベルファスト〈平和の壁の街〉`

### 地方・王国・辺境

形式:

- `固有名 + 地方 / 王国 / 公領 / 辺境 / 諸島`

例:

- `アルヴェイン地方`
- `エルス王国`
- `ノルド辺境`

### 組織・制度

形式:

- `紋章語 / 色 / 守護語 + 騎士団 / 修道会 / 商会 / 評議会 / 同盟`

例:

- `白冠修道会`
- `灰潮商会`
- `銀環評議会`
- `黒鹿騎士団`

### 人物

形式:

- 主表示: 短い固有名
- 補助表示: 役職、所属、異名

例:

- `セルカ`
  - 補助: `停戦守`
- `リス`
  - 補助: `鐘守の祈祷師`
- `ノルヴ`
  - 補助: `坑道案内人`

### 遺物・装備

形式:

- `意味語 + の + 器物名`
- `素材語 + 器物名`
- mythic alias が必要な場合だけ括弧を使う

例:

- `白誓の指輪`
- `灰潮の灯`
- `冠雪の誓剣`
- `火蜥蜴の燐石`
- `火蜥蜴（サラマンダー）`

### 魔法・技法

形式:

- `作用 + 名詞`
- `元素 / 伝承語 + 術 / 印 / 詩 / 祈り`

例:

- `潮返し`
- `白火の印`
- `霧歩き`
- `冬鐘の祈り`

## 禁止パターン

### raw English をそのまま主表示にする

- `White Oath Ring`
- `Saltfinder Vial`

### 辞書を引かないと意味が通らない語を主表示にする

- 初見で意味が取れない古語
- 説明を読まないと用途が分からない造語
- 小説読者でも常用とは言いにくい特殊語

### 漢字と読みが離れすぎる

- `澱舟泊（テイシュウ）`
- `白祠圏（ホワイトシュライン）`

### 名詞を積んだだけで意味が取れない

- `渡しの場で誓いを立てた者の吐息を閉じ込めた環`
- `保留には鈍く応じる`

### 固有音だけで何の場所か分からない

- `ベルタイド`
- `アッシュマーチ`

## 書き換え例

| 旧表示 | 方向性 | 新しい主表示 | 補助表示 |
| --- | --- | --- | --- |
| `White Oath Ring` | 直訳英語をやめる | `白誓の指輪` | `誓約を刻む古い指輪` |
| `Belltide Wharf` | 港だと分かる形にする | `ベルファスト港` | `潮見の港町` |
| `Saltfinder Vial` | 用途を日本語にする | `塩見の小瓶` | `封印の歪みを見る試薬瓶` |
| `セルカ〈トルース・ウォーデン〉` | 役職を別表示に分離 | `セルカ` | `停戦守` |
| `Wardbrand Longsword` | 装備の格と用途を出す | `冠雪の誓剣` | `誓約を担う長剣` |

## UI 実装ルール

- shell / hub / codex では必ず `ui_label` を使う。
- 補助表示が必要な場所だけ `ui_subtitle` を出す。
- reading は codex 詳細以外では原則非表示。
- true_name は reveal 状態と連動させる。
- ラベルと説明文を同じ場所に詰め込まない。
- 分からない語を、説明なしでカード見出しに置かない。

## 外部辞典を合わせるときのルール

- 次に入る外部辞典は、この文書より下位ではなく、`候補語の供給源` として扱う。
- ただし採用基準はこの文書を優先する。
- 既存の `Fantasy_Naming_System_Core` のような外部辞典は、まず `surface_name` と `semantic_tags` の source として受ける。
- その `surface_name` を UI 主表示へそのまま出すかどうかは、この文書の可読性 gate で別途判定する。
- 辞典に載っていても、次のものは主表示に採らない。
  - 初見で意味が通らない語
  - 誤読しやすい語
  - 誤解を生みやすい語
  - 雰囲気先行で用途が見えない語

採用時の優先順位:

1. 外部辞典の候補
2. この文書の常用・可読性基準
3. UI の役割
4. 世界観との整合

## 候補語の評価チェック

- これを主表示に置いたとき、プレイヤーは 1 秒で意味を取れるか
- 読みを知らなくても機能やカテゴリが分かるか
- 一般読者か小説読者にとって常用に近いか
- 似た別語へ誤解しないか
- 雰囲気を引いたあとでも、名前として残るか

## この方針を今の repo に適用するときの注意

- 既存の `display_naming.py` のような「英語化・カタカナ化」は、この文書の方向とは一致しない。
- 次の置換では、`英語風 alias` ではなく `日本語主表示 + 補助表示` に切り替える。
- `front_hubs.py` の装備名・遺物名も同じ基準で見直す。
